How it works

A trip, from schedule to five stars

Every step below is a real endpoint you can call from the docs, in this order.

1

Schedule

An admin sets the route, time, fare and seat capacity for a trip.

2

Book a seat

A rider browses available rides and reserves a seat, with capacity enforced server-side.

3

Ride, live

The driver starts and ends the trip, and every status change is pushed over a WebSocket.

4

Pay & rate

Chapa checkout settles the fare, then rider and driver rate each other.

Test it yourself

From empty database to a paid, rated trip

No seed data and no signup flow. The interactive docs are the client.

  1. Bootstrap an admin

    In the docs, open POST /admin-register and send it with no auth. On an empty database it creates the first superadmin and returns a JWT. Paste it into Authorize.

  2. Register a rider and a driver

    Under Auth, register one of each. The driver then adds a vehicle with POST /vehicle.

  3. Schedule and book a trip

    As the admin create a trip, then as the rider book a seat on it.

  4. Watch it change live

    Connect a Socket.IO client to /rides with your JWT, join the trip room, and start and end the ride as the driver.

  5. Pay and rate

    The rider calls POST /pay-ride for a Chapa checkout URL, and once the trip is done both sides submit ratings.

Built to hold up

Security and production hygiene

The unglamorous parts that decide whether a backend survives real users.

TLS to every service

Aiven MySQL and Upstash Redis connections are certificate-verified, not opportunistic.

Real logout

Tokens are blacklisted in Redis on logout and checked on every authenticated request.

Server-side role checks

Admin actions are gated by level, read from the verified token and never from the request body.

Trusted amounts only

Payments are charged from the fare on file, so a client can't underpay by editing a request.

Rate limiting

Login, register and reset endpoints are throttled through Redis, so brute force gets a 429.

CI on every push

Lint, the full test suite and a Docker build gate every merge, then Render deploys main.
