Capabilities

Not a CRUD demo.

Every module below is live, documented, and callable — including the parts that usually get mocked out: real payment webhooks, real-time sockets, and a self-bootstrapping admin.

JWT auth & blacklist

Role-scoped tokens for riders, drivers and admins. Logout actually invalidates a token via a Redis blacklist — not just client-side deletion.

Scheduled trips

Admins set routes and departure times; riders reserve seats against live capacity; drivers move a trip through its full status lifecycle.

Chapa payments

Charges are server-computed from the trip fare, never trusted from the client, and confirmed only after a signature-verified webhook — behind a swappable PaymentGateway interface.

Ratings & reviews

Riders and drivers rate each other after a completed trip; aggregate scores are recomputed atomically and surfaced on profiles.

Live WebSocket status

A /rides namespace pushes ride-status updates the instant a driver starts, ends or cancels a trip — backed by Redis pub/sub so it scales horizontally.

Admin console

Block/unblock users, review reports, inspect earnings and transaction history — gated by a first-admin bootstrap so the console is reachable from a fresh database.

Rate limiting

Auth and registration endpoints are throttled through the same Redis instance backing the token blacklist — brute-force attempts get a 429, not a timing oracle.

Profile & vehicle media

Profile photos and driver vehicle records, validated and stored with an explicit MIME/extension allowlist — not trusted from a client-supplied filename.

Try it yourself

Everything below runs from Swagger.

No seed data, no separate signup flow — the interactive docs at /apidocs/ are the actual client. This is the fastest path from a cold database to a completed, rated, paid trip.

1

Open the API docs and bootstrap an admin

Expand Admin → POST /admin-register and send it with no Authorization header. On an empty database this creates the first superadmin and hands back a ready-to-use JWT — click Authorize and paste it in.

2

Register a rider and a driver

Under Auth, register one of each. The driver then registers a vehicle via Vehicle → POST /vehicle before it can be assigned to a trip.

3

Schedule and book a trip

As the admin, create a trip under Ride Management. As the rider, book a seat on it — capacity is enforced server-side.

4

Watch status change in real time

Open a Socket.IO client against the /rides namespace (JWT passed in the connection auth payload) and join the trip's room. Start and end the ride as the driver — the update arrives over the socket, not a poll.

5

Pay and rate

The rider calls Payments → POST /pay-ride for a Chapa checkout URL, and once a trip is completed, both sides call their respective Ratings endpoint.

Built to hold up

Security & production hygiene

TLS everywhere. Aiven MySQL and Upstash Redis connections are both certificate-verified, not opportunistic.
Real logout. Tokens are blacklisted in Redis on logout, checked on every authenticated request.
Role & level checks are server-side. Admin-management actions are gated by superadmin level, verified from the decoded token — never trusted from the request body.
Server-computed charges. Payment amounts come from the trip's fare on file, never from client input.
Validated input. Request bodies are parsed and typed before they touch a query — malformed input gets a clean 400 with the actual reason.
CI on every push. Lint, the full test suite, and a Docker build all gate merges to main.
